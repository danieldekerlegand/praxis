### Learnings for future iterations

- **The generator generates, it never constructs.** Every gate/rubric rule already has one
  owner; a tasklist that ran its own loop would be a second definition of "complete". The
  stories name `python3 -m praxis.backfill <dir>` / `python3 -m praxis.construct --subject
  <slug>` and nothing else.
- **Grade before writing, one level up.** `tasklist_failures()` is the same idiom as
  `construction_failures` / `checkset_failures`, and `write_tasklist` refuses a document
  that fails it — and refuses to overwrite an active or retired tasklist, whose `passes`
  flags are chief's bookkeeping.
- **Chief facts worth not re-deriving** (from ~/Development/chief, both tasklists completed):
  `docs/guides/headless-invocation.md` — `chief run --headless` prints `chief: run-id=<id>`,
  `run-file=`, `events=`, `state=` before the loop and one final
  `chief: outcome=` / `exit=` / `summary={…json…}`; exit codes 0 merged · 2 config error ·
  3 no-work · 4 verify-failed · 5 conflict · 6 failed · 7 paused.
  `docs/guides/local-inference-preset.md` — `chief run --local` (`--preset local`,
  `CHIEF_PRESET=local`) needs `CHIEF_LOCAL_ENDPOINT` + `CHIEF_LOCAL_MODEL` and errors rather
  than falling back to a paid provider. US-2 consumes exactly these two documents.
- **A criterion naming another repo fails the run UNSATISFIABLE** before the first turn
  unless the tasklist declares `crossRepo` — so generated criteria stay inside the worktree
  (a test asserts it). This tasklist (82) declares `crossRepo: ["chief"]`, which is why its
  own criteria may name `chief:80-…`.
- **A generated subject's notebooks land OUTSIDE the repo** (storage root), so a
  `build-<slug>` tasklist's branch diff is not its evidence — recorded badge/gate counts are.
- Test cost: the `domain` fixture in `tests/test_backfill.py` (importable, along with
  `subjects_root`) costs ~5s per test because it really constructs and validates notebooks.
  Document-shape tests use a synthetic `Unit` instead; only selection tests pay for it.

## US-2 — Drive the run headlessly through chief's programmatic entry point, cheaply (commit 09d0094)

Added `praxis/headless.py`: tasklist.py's other half. It **starts** a generated tasklist as
a Chief run and reads the result back, consuming two chief contracts BY REFERENCE (a CLI
shape + two env vars; no import, no path into another checkout).
  - `records(stdout)` keeps only `chief: <key>=<value>` lines — the anti-scraping boundary
  - `parse_run(stdout, rc)` -> `HeadlessRun`: outcome from `summary=` JSON, then `outcome=`,
    then the exit table. RAISES on a stream with no run-id, on a non-JSON summary, and on a
    `chief: exit=` that disagrees with the process's own status.
  - `LocalPreset` / `routing()` — `--preset=local` + CHIEF_LOCAL_ENDPOINT/MODEL, never
    `--provider`/`--model`, no default host; refuses BEFORE generating or spawning.
  - `run_units` / `ensure_tasklist` / `unfinished` / CLI (`plan` | `run`), exiting with
    chief's own exit code.
Added `tests/test_headless.py` (35 tests, scripted fake `chief` on disk),
`docs/reference/chief-powered-construction.md` (linked from docs/README.md) and a CLAUDE.md
section.

### Learnings for future iterations

- **A test that calls a CLI entry point can write into the working tree.** `headless.main`
  resolves `tasks/chief` off `tasklists.repo_root()`, so the first CLI test generated a real
  `tasks/chief/gate-01-*.json` into the branch. Fix is `monkeypatch.setattr(tasklists,
  "repo_root", lambda: tmp_path)`. Check `git status --porcelain tasks/` after adding any
  test that goes through a `main()`.
- **Order the refusal before the write.** The same bug showed up in the product: `run_units`
  generated the tasklist and *then* discovered the preset was unconfigured, leaving a file
  behind for a run that never started. `routing()` is now resolved first in both entry
  points, and a test asserts `tmp_path/tasks` does not exist after the refusal. Generalizes:
  every "grade before you write" rule in this repo has an "and check the preconditions
  before you write" twin.
- **The doc-link gate matches bare `docs/...` paths from the REPO ROOT**, so citing
  chief's `docs/guides/headless-invocation.md` in prose is a dead link here. Wrap a
  foreign repo's doc path in backticks — the regex's lookbehind excludes a backtick, and
  that is also how it reads correctly.
- **Chief's contract, as consumed** (verified against ~/Development/chief's shipped docs +
  `bin/chief`): `--preset=<name>` IS accepted (`--preset)`/`--preset=*`/`--local` all parse);
  `--headless` is a flag on the run you already know; run-id is printed before the loop and
  `outcome=`/`exit=`/`summary=` after it; exit 2 means the run never started, so there is
  no run-id line to insist on (that is the unconfigured-preset path).
- The full suite is ~6 minutes now. Run it in the background and keep working; run it once
  more after the last edit rather than reporting a number from a stale run.
