## Codebase Patterns

- **The four writes are define → scaffold → construct → checks.** Adding a fifth capability
  usually means *selecting targets* for one of them, not writing a new writer. `praxis/backfill.py`
  is the shape: it computes a target list and calls `construct_each`.
- **`construct_each` is the only batch loop.** `construct_domain`, `construct_subject` and now
  `backfill_domain` are one-liners over it, which is where resumability comes from.
- **`checks.publish_graded_cells(nb, checks, target)` is the single write path for graded cells**:
  annotate → `nbgrader validate` a staging copy → release only what nbgrader produced. Never
  hand-annotate a notebook in a new caller.
- A released notebook is ASCII-escaped JSON (`json.dumps` default) while a constructed one is
  not — comparing notebook *bytes* before/after a gate is written will fail on the escaping
  alone. Compare cell sources instead.
- The full suite takes ~3 min (nbgrader subprocesses); `tests/test_backfill.py` alone ~50s.

## 2026-08-22 — US-1 Gate one domain's notebooks by reusing the shipped check machinery

**What I did**
- Added `praxis/backfill.py`: `domain_targets()` (every notebook on disk, `filesystem` domains
  resolved through `construct.topic_for_path` so nested legacy notebooks work), `is_complete()`,
  `is_gated()`, `backfill_targets()` and `backfill_domain(domain, *, limit=None, **kwargs)`.
  It gates nothing itself — targets go to `construct_each(..., checks=True)`.
- `is_gated()` is `needs_checks()` re-expressed against 84's schema: a sidecar **and**
  `checks.graded_cells(nb)`. A sidecar on its own is a half-migrated gate, not a gate.
- Fixed the resume path in `construct._with_checks`: it annotated only *freshly constructed*
  notebooks, so a ✅-but-ungated topic gained a sidecar and no graded regions — exactly the
  parallel format the nbgrader adoption replaced, and exactly the state this whole band is
  backfilling. Now it annotates when the notebook carries no graded cells yet.
- `generate_checks` gained one no-model repair: a stored set whose cells never landed is
  republished from the sidecar (status `generated`, detail "graded cells written from the
  stored set"), so the half-migrated state converges instead of being re-selected for ever.
- Factored the staging/validate/release block out of `generate_checks` as
  `checks.publish_graded_cells()`; added `checks.graded_cells()` + `CHECKS_EXTENSION` as the
  one reader of the `praxis` cell namespace.
- `tests/test_backfill.py` (11 tests) and an updated
  `test_a_notebook_that_was_already_complete_still_gains_its_checks` in `tests/test_construct.py`
  (the prose is preserved; the graded cells are new).
- Documented the module in `CLAUDE.md` under **Knowledge checks**.

**Verification**
- `python3 -m pytest -q tests/` → **929 passed, 1 skipped** in 199s.
- `python3 scripts/validate_nbgrader.py notebooks` → **24 notebooks, 0 failures**.
- Seed-library coverage is unchanged at **24/245** — this story shipped the mechanism; no
  seed notebook was gated, because gating one needs a model key (US-2 drives the batches).

**Learnings for future iterations**
- The 84 band left the *resume* path (already-✅ notebook gains checks) writing only the
  sidecar. Any story that assumed "the schema is adopted everywhere" needs to check the
  caller, not just `annotate_notebook`.
- `release_notebook` re-serializes with `json.dumps(..., indent=1)`, which ASCII-escapes.
  The 24 already-gated seeds are ASCII-escaped too, so backfilled notebooks match them.
- `nbgrader_validate()` returns `[]` early for a *released* notebook (no `BEGIN SOLUTION`
  left to execute), so asserting it on the published file is a schema check, not a runtime
  one. The runtime bar is `checkset_failures(verify_code=True)` plus the validate that runs
  against the **staging** (authored) copy inside `publish_graded_cells`.
- `FakeClient` in `tests/test_construct.py` answers both call kinds (notebook vs checks, told
  apart by system prompt) and records them separately — reuse it rather than writing another.

## 2026-08-22 — US-2 Batch the backfill across the 14 domains, resumably

**What I did**
- `praxis/backfill.py` gained the library batch, three functions and no new writer:
  `library_domains()` (the seed manifest, read live off `curriculum.DOMAINS` the way
  `promote`/`library_index` read it; generated subjects are opt-in via `subjects=True`),
  `library_targets(domains, depth=1, limit=None)` and `backfill_library(...)` — a
  one-liner over `construct_each`, exactly like `construct_domain`/`construct_subject`.
- **The order is the only thing the batch adds.** `library_targets` interleaves the
  per-domain backlogs: `depth` targets from each domain before any domain's next, so a
  capped or interrupted run leaves every domain a little gated instead of three finished
  and eleven with none. `depth=1` (pure round robin) is the default; a depth larger than
  the biggest backlog degenerates to domain-at-a-time.
- `coverage(domains)` returns per-domain `(domain, gated, complete, total)` — what the
  fractions below were measured with. (Band 80 is the coverage *tracker*; this is the six
  lines the batch needs to report itself, not that product surface.)
- 5 new tests in `tests/test_backfill.py` over a two-module fixture: manifest order,
  breadth-first vs `depth=2`, a capped pass gating one topic in *each* domain, a full
  batch that gates only the ungated (the already-gated notebook and the scaffold come
  back byte-identical) and whose re-run returns `[]` with zero client calls, and coverage.
- Documented the batch in `CLAUDE.md` under **Knowledge checks**.

**Verification**
- `python3 -m pytest -q tests/` → **934 passed, 1 skipped** in 217s (16 in test_backfill).
- `python3 scripts/validate_nbgrader.py notebooks` → **24 notebooks, 0 failures**.

**Learnings for future iterations**
- No LLM key exists in the chief environment. Any story whose acceptance criteria imply
  *moving* the 24/245 number needs a keyed run — the mechanism can be shipped and proved
  against fakes, the coverage number cannot be moved here. Say which one you did.
- `library_targets` takes `(Domain, Subject|None)` pairs, not Domains, because
  `topic_path` resolves a subject's module under `subjects_dir()`. Tests build a real
  two-module subject in tmp and pass the pairs; the default is the seed manifest.
- Each gated notebook costs ~5s (the `nbgrader validate` subprocess), so a test that
  gates four is a ~25s test. Keep batch fixtures small — the suite is now ~3m40s.
