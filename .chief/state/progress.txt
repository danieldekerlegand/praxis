## Codebase Patterns

*(carried forward from 80-gating-coverage-tracker, plus this band's additions)*

- **Library view model = one place.** `launcher.app.build_model()` → `_topics_for()` →
  `_gated()` folds in every per-topic fact (status, gated, locked, passed, checks, graded).
  Count by folding over those rows, never by re-scanning `notebooks/` — a second scan is a
  second definition and it will drift.
- **Two halves of "gated".** `gated` = a loadable answer key sidecar. `graded` = nbgrader
  graded cells actually in the .ipynb (D10 / band 84). `backfill.is_gated()` and
  `praxis.coverage.is_gated()` both require BOTH. A sidecar with no cells is half-migrated.
- **praxis/ must not import launcher/ at module level.** When a core module needs the view
  model, import `launcher.app` *inside* the function.
- **Module convention** (`praxis/gap.py`, `praxis/audit.py`): long "why" docstring with a
  CLI stanza, then `_main(argv)` + `if __name__ == "__main__"`.
- **Toolchain in a fresh worktree.** There is NO `.venv` here; the system `python3`
  (/usr/local/bin/python3) already has pytest + nbformat + nbgrader, but **not fastapi**.
  Without the launch extra `tests/test_launcher_api.py` skips as a whole module (1 skip
  hiding 56 tests) and the suite reads ~942 collected. Install it before claiming green:
  `python3 -m pip install -e '.[launch]'` → 1001 tests, 0 skipped.
- **The audit/regenerate policy already exists**, in `docs/explanation/seed-refresh-policy.md`:
  FLAGGED-FOR-HUMAN is the default, FORCE-REGENERATE needs an explicit per-notebook opt-in,
  and a failed candidate leaves the existing file byte-identical. US-3 of this band is that
  same shape pointed at gates rather than notebooks — reuse the vocabulary.
- **`tests/test_audit.py` and `praxis/audit.py` already exist** (the seed-refresh audit).
  US-1's checkset audit should be read against them before starting a new module.
- **docs/README.md is a required index** — "a document not linked here does not exist".
  A new doc that isn't linked there is invisible; the doc-link check is a ratchet on *dead*
  links (`node scripts/check-doc-links.mjs --ratchet --base main`), so it won't catch it.

### Learnings for future iterations

- **The decisive fact was architectural, not maintenance.** jupyterquiz's *render input is
  the answer key* — a question is an `answers` array whose entries carry `correct`, and
  grading runs in the browser against it. There is no "rendering only" configuration; using
  it means shipping the key past `checks.learner_check()`. Its own README offers
  base64-embedding as the answer, which is obfuscation, not a boundary.
- **This is the mirror of the call `chief/85` already made.** JupyterLite was adopted
  precisely because the runtime can move into the browser while gate authority stays in a
  process the learner does not control. jupyterquiz cannot take that shape. When the next
  scan proposes a learner-facing dependency, that is the first question to ask of it.
- The commit trailer in `.chief/agent-context.md` names Opus 4.8; this iteration ran on
  Opus 5 and the trailer records the model that actually did the work.

## US-1 — Audit backfilled checksets for fabricated or trivial questions (262d731)

New module `praxis/gateaudit.py` + `tests/test_gateaudit.py` (15 tests), plus a
paragraph in `CLAUDE.md` beside the coverage one.

**What it audits, and what it deliberately does not.** Two gates already ran before a
set landed: `nbgrader validate` (wellformedness + hidden tests execute) and
`checks.checkset_failures()` (gradable, reference solution run against its own test).
Neither can say the question is trivial. The audit calls `checkset_failures` for the
gradability half — reported under its own key, never merged — and owns only four
measured rules:

- `choice` giveaway: word coverage of the correct option by the prompt, **scored against
  the best distractor's coverage**, so a question reusing its own subject vocabulary is
  not mistaken for one handing over its answer.
- `short` key quoted in its own prompt / copied verbatim out of the notebook body.
  `body_text()` drops the Praxis-owned graded cells first — `annotate_notebook()`
  publishes the prompts into the notebook, so without that every gate looks copied.
- `code` test that passes an **empty submission or the starter stub** — `run_code_check()`
  pointed the other way. Generation proves the reference solution passes; this proves
  nothing else does. Measured, not read, so `assert True` and a tautological assert both
  fall out of the same rule.
- two near-identical prompts in one set (Jaccard over content words).

**Measured before written.** Every threshold was calibrated against the 24 shipped gates
(see the notes field for the numbers). All 24 are `generated_by: "hand-authored"` — the
79 backfill has produced nothing on disk in this worktree, so the hand-built set is both
the corpus and the bar, and `test_every_shipped_seed_gate_is_clean` pins 0 flagged.

Observed: `python3 -m pytest -q tests/` **1016 passed, 0 failed** (339s, launch extra
installed). `python3 scripts/validate_nbgrader.py notebooks` **24 notebooks, 0 failures**.
`python3 -m praxis.gateaudit` **24 gates (144 checks), 0 flagged**, 2.3s.

### Learnings for future iterations

- **Calibrate a threshold against the shipped 24 before writing the rule, not after.**
  A ten-line probe script over `notebooks/**/*.checks.json` printed the worst genuine
  score for each candidate rule; two candidates died there (option-length ratio — the
  genuine max is 2.8x, no headroom; and any body-overlap rule below 0.7). Repeat that
  probe before adding or tightening a rule in US-2/US-3.
- **US-2 wiring, already thought through.** `set_quality_failures(doc, notebook=...,
  verify_code=...)` is shaped to drop straight into `checkset_failures`'s write path, and
  `quality_failures(check, ...)` into `check_failures`. Import it **inside** the function
  in `praxis/checks.py` — `gateaudit` imports `checks` at module level, so a module-level
  import back is a cycle. The `notebook=` argument defaults to `""` (the copied-out-of-
  the-page rule simply does not run without it), and `verify_code=False` skips the
  subprocess runs, so `needs_checks()`'s cheap load path stays cheap for free.
- **One landmine for US-2:** the sample builders in `tests/test_checks.py` (`choice()` /
  `short()`) template the prompt off the section name, so two of them across sections
  score ~1.0 on the duplicate rule. Wiring the rule into `checkset_failures` will fail
  those tests until the fixtures are given distinct prompts — which is the right fix, not
  a reason to loosen the rule.

## US-2 — Tighten checkset_failures so a trivial set can never be written (63c1036)

The four rules US-1 measured now run on the **write path**, not only as a report.
`praxis/checks.py`:

- `check_failures(..., quality=None, notebook="")` appends `gateaudit.quality_failures`;
  `checkset_failures(..., quality=None, notebook="")` passes it through and adds
  `gateaudit.duplicate_failures` across the set. Both import gateaudit *inside* the
  function — gateaudit imports `praxis.checks` at module level, so the dependency runs
  one way at import time.
- **`quality` follows `verify_code`.** That one line is the whole boundary: the cheap
  load path (`needs_checks()`, and generation's already-generated skip, both
  `verify_code=False`) runs neither half, so it stays cheap *and* a gate written before
  the bar existed is skipped rather than silently re-judged or rewritten. Re-auditing
  those is US-3's explicit pass. `quality=False` is also what `gateaudit.audit_checkset`
  now passes, so its two halves stay reported separately instead of double-counting.
- `generate_checks` passes `notebook=body_text(nb)` — the copied-out-of-the-page rule is
  the one rule that needs the page. `praxis/promote.py` does the same with the notebook
  it had already read.

Files: `praxis/checks.py`, `praxis/gateaudit.py`, `praxis/promote.py`,
`tests/test_checks.py`, `CLAUDE.md`.

Observed: `python3 -m pytest -q tests/` **1025 passed, 0 failed** (313s);
`CHIEF_BASE_BRANCH=main bash .chief/verify.sh` → **verify: PASS**;
`python3 scripts/validate_nbgrader.py notebooks` **24 notebooks, 0 failures**;
`python3 -m praxis.gateaudit` **24 gates (144 checks), 0 flagged**.

Nine new tests: five parametrized fabricated/trivial sets (answer given away, key quoted
in its own prompt, a `test` passing an empty submission, a `test` passing the starter
stub, the same question twice) each fail with that rule's own sentence and leave nothing
on disk; a `short` whose `expected` is copied verbatim out of the notebook body is
rejected; the grader's sentence is what the model's **second attempt** is repaired with;
the cheap load path returns `[]` for a set the full bar flags; and all 24 shipped seed
gates still pass the tightened bar.

### Learnings for future iterations

- **The fixture landmine US-1 predicted was real and was the only test change needed.**
  `tests/test_checks.py`'s `choice()`/`short()` templated one prompt off the section
  name, scoring 0.75–1.00 on the duplicate rule; they now carry a per-section prompt
  (`CHOICE_PROMPTS` / `SHORT_PROMPTS`, with the old template as the fallback for a
  section not in the map). `tests/test_construct.py`, `test_backfill.py` and
  `test_launcher_api.py` all import `good_checks` from there, so fixing it once fixed
  every caller — check that import graph before duplicating a fixture.
- **US-3 is already half-specified by this shape.** The "flag, don't rewrite" rule it
  wants is what `quality` following `verify_code` already produces: a pre-tightening gate
  on disk is *skipped* by `needs_checks()`, so US-3 is (a) a pass that calls
  `checkset_failures(doc, notebook=body_text(nb))` — the tightened grader, not a parallel
  one — over gates already written, and (b) an explicit per-notebook regeneration that
  goes through `generate_checks(force=True)`, which now cannot write a set failing the
  new bar. `docs/explanation/seed-refresh-policy.md`'s FLAGGED-FOR-HUMAN /
  FORCE-REGENERATE vocabulary is the one to reuse.
- **Cost of the tightening, measured:** a `code` check now costs up to 3 subprocess runs
  at generation (reference solution, empty submission, starter stub) instead of 1. The
  full suite went 313s vs ~339s before — no meaningful change, because sets carry ~1 code
  check each.
