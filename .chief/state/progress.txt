## Codebase Patterns

*(carried forward from 80-gating-coverage-tracker, plus this band's additions)*

- **Library view model = one place.** `launcher.app.build_model()` → `_topics_for()` →
  `_gated()` folds in every per-topic fact (status, gated, locked, passed, checks, graded).
  Count by folding over those rows, never by re-scanning `notebooks/` — a second scan is a
  second definition and it will drift.
- **Two halves of "gated".** `gated` = a loadable answer key sidecar. `graded` = nbgrader
  graded cells actually in the .ipynb (D10 / band 84). `backfill.is_gated()` and
  `praxis.coverage.is_gated()` both require BOTH. A sidecar with no cells is half-migrated.
- **praxis/ must not import launcher/ at module level.** When a core module needs the view
  model, import `launcher.app` *inside* the function.
- **Module convention** (`praxis/gap.py`, `praxis/audit.py`): long "why" docstring with a
  CLI stanza, then `_main(argv)` + `if __name__ == "__main__"`.
- **Toolchain in a fresh worktree.** There is NO `.venv` here; the system `python3`
  (/usr/local/bin/python3) already has pytest + nbformat + nbgrader, but **not fastapi**.
  Without the launch extra `tests/test_launcher_api.py` skips as a whole module (1 skip
  hiding 56 tests) and the suite reads ~942 collected. Install it before claiming green:
  `python3 -m pip install -e '.[launch]'` → 1001 tests, 0 skipped.
- **The audit/regenerate policy already exists**, in `docs/explanation/seed-refresh-policy.md`:
  FLAGGED-FOR-HUMAN is the default, FORCE-REGENERATE needs an explicit per-notebook opt-in,
  and a failed candidate leaves the existing file byte-identical. US-3 of this band is that
  same shape pointed at gates rather than notebooks — reuse the vocabulary.
- **`tests/test_audit.py` and `praxis/audit.py` already exist** (the seed-refresh audit).
  US-1's checkset audit should be read against them before starting a new module.
- **docs/README.md is a required index** — "a document not linked here does not exist".
  A new doc that isn't linked there is invisible; the doc-link check is a ratchet on *dead*
  links (`node scripts/check-doc-links.mjs --ratchet --base main`), so it won't catch it.

### Learnings for future iterations

- **The decisive fact was architectural, not maintenance.** jupyterquiz's *render input is
  the answer key* — a question is an `answers` array whose entries carry `correct`, and
  grading runs in the browser against it. There is no "rendering only" configuration; using
  it means shipping the key past `checks.learner_check()`. Its own README offers
  base64-embedding as the answer, which is obfuscation, not a boundary.
- **This is the mirror of the call `chief/85` already made.** JupyterLite was adopted
  precisely because the runtime can move into the browser while gate authority stays in a
  process the learner does not control. jupyterquiz cannot take that shape. When the next
  scan proposes a learner-facing dependency, that is the first question to ask of it.
- The commit trailer in `.chief/agent-context.md` names Opus 4.8; this iteration ran on
  Opus 5 and the trailer records the model that actually did the work.
