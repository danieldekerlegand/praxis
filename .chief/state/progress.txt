## Codebase Patterns

- **Library view model = one place.** `launcher.app.build_model()` → `_topics_for()` →
  `_gated()` is where every per-topic fact the app knows gets folded in (status, gated,
  locked, passed, checks, and now `graded`). Anything that wants to *count* notebooks
  should fold over those rows, not re-scan `notebooks/` — a second scan is a second
  definition and it will drift.
- **Two halves of "gated".** `gated` = a loadable answer key (drives `module_gates()`,
  locks the next topic). `graded` = nbgrader graded cells actually in the .ipynb
  (decision D10 / band 84). `backfill.is_gated()` requires both; so does
  `praxis.coverage.is_gated()`. A sidecar with no cells is a half-migrated gate.
- **praxis/ must not import launcher/ at module level.** No praxis module does. When a
  core module needs the view model (`coverage.library_report`), import `launcher.app`
  *inside the function* so the arithmetic stays importable with no launch extra.
- **Module convention** (see `praxis/gap.py`, `praxis/audit.py`): long "why" docstring
  with a CLI stanza, then `_main(argv)` + `if __name__ == "__main__"`.
- **No .venv in a fresh worktree.** `.chief/verify.sh` bootstraps one, but to run tests
  by hand first: `uv venv .venv && uv pip install --python .venv/bin/python -e '.[launch,dev]'`.
  Without fastapi the launcher tests silently skip — the interpreter that runs pytest
  must also have nbgrader (praxis.checks resolves its console script beside it).
- **Full suite is ~5 min** (996 tests). `tests/test_launcher_api.py` alone is ~90s.

### Learnings for future iterations

- The PRD's "off the same `_gated()`/`module_gates()` signal" and D10's "gated means
  nbgrader cells" pull in different directions: `module_gates()` derives `gated` from the
  **sidecar answer key**, not from cells. Resolved by adding `graded` as a second row
  field rather than redefining `gated` — redefining it would have changed what
  `/api/study` locks (a key-but-no-cells notebook still serves real questions through
  the UI, so it *does* gate), which is out of this band's scope. The tracker requires
  both. Today the two sets are identical (24 = 24), so nothing is hidden by the choice.
- `_library_domains()` reads `launcher.app.DOMAINS`, bound at import from `curriculum`.
  To test against a fixture library, `monkeypatch.setattr(launcher_app, "DOMAINS", [])`
  — patching `curriculum.DOMAINS` does nothing.
- Don't pin `24` in a test: band 79's backfill moves it. `test_the_shipped_library_report_agrees_with_the_notebooks_on_disk`
  pins the *agreement* between the report and an independent file scan instead, so it
  stays green as coverage climbs.
- **US-2 next**: the endpoint. `coverage_report(build_model()["domains"])` is one line in
  `launcher/app.py`; note `build_model()` is already called by `/api/library`, so folding
  a `coverage` key onto that response costs nothing extra, while a separate
  `GET /api/coverage` costs a second `build_model()` pass. Either satisfies US-2's
  first criterion; folding onto `/api/library` is cheaper and keeps one poll.

### Learnings for future iterations

- **Fold, don't add an endpoint.** A `GET /api/coverage` would have cost a second
  `build_model()` pass over every notebook for a number the library response was already
  one line from carrying. Folding also means the shell's *existing* refetch-after-write
  paths (construction settles → `fetchLibrary`) update the tracker for free.
- The direction of the dependency matters: `build_model()` imports `coverage_report` at
  module level (fine — `praxis/coverage.py` imports nothing from `launcher` at module
  level), and `library_report()` reads the folded key. Keep it that way; recomputing in
  `library_report` would be a second call site of the same fold.
- `zip(domains, coverage["domains"])` is safe because `coverage_report` is a list
  comprehension over the same sequence — order-preserving by construction, and the API
  test pins `dir`/`name` agreement so it stays that way.
- Jinja lookup of a per-domain row is
  `{% set cov = (coverage['domains'] | selectattr('dir','equalto', active.dir) | list | first) %}`
  — `selectattr` on dict items works because Jinja's attribute lookup falls back to
  subscript.
- A quick before/after demo without polluting the suite: drop a throwaway
  `tests/test_zz_*.py` that imports the fixtures from `tests/test_coverage.py`
  (`from test_coverage import LIBRARY, library`), run it with `-s`, then delete it.
- The worktree ships no `ui/node_modules` either — `npm install` in `ui/` first, or
  `npm run build` dies on `tsc: command not found`.
