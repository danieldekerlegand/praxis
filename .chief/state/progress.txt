## Codebase Patterns

- **No LLM key is configured in this worktree.** `praxis.llm.load_config()` raises
  `LLMConfigError`; there is no `~/.config/praxis/config.json` and no `ANTHROPIC_API_KEY`
  / `OPENAI_API_KEY` / `AGORA_BASE_URL`. The gating batches therefore cannot be driven by
  a provider here — use `praxis/authored.py` (added in US-1), which serves the model's
  half from `<slug>.checks.draft.json` beside the notebook while every grading and write
  rule downstream runs unchanged.
- **Author a draft, then grade it before running the batch.** `/tmp/grade.py` pattern:
  `generate_checks(domain, topic, client=AuthoredClient.for_domain(domain), attempts=1,
  write=False, force=True)` gives the grader's sentences in ~0.1s without touching disk.
  Iterate there; run `python3 -m praxis.authored run <DIR>` once the drafts are clean.
- **Drafts are git-ignored** (`*.checks.draft.json`). They persist in the worktree across
  iterations but never reach a commit — the accepted `<slug>.checks.json` is the artifact.
- **The suite pins gate counts.** Anything that raises coverage will fail
  `tests/test_gateaudit.py`, `tests/test_regate.py` and
  `tests/test_launcher_api.py::test_an_ungated_seed_notebook_is_open_and_says_so` unless
  those assertions are floors/properties. US-1 converted all three; if a new one appears,
  convert it rather than freezing the corpus.
- **`module_gates()` locks ungated topics too.** A topic with no checks is locked while an
  *earlier* topic in the same module is gated and unfinished. So gating a domain locks the
  rest of that domain behind its first gate — intended (sequential progression), but it
  invalidates any test that assumes "ungated implies unlocked".
- **The full suite is ~6.5 minutes**; `scripts/validate_nbgrader.py notebooks` is instant
  (it no-ops on released notebooks — the real nbgrader run happens inside
  `publish_graded_cells` on a staging copy). Budget for the pytest run, not the validator.

**Learnings for future iterations**
- **Author code checks as stdlib re-implementations of the notebook's own mechanism.**
  Every one of the 38 does this (the lifecycle handshake, the durable task resumed by id,
  the state reducer that clobbers without a merge rule, the blank that saves a double
  letter, the soft alignment that has a gradient where a repeat has none). It is the only
  reliable way to clear `gateaudit` *and* be worth grading, and it makes the `short`
  checks write themselves because you already know what the mechanism is FOR.
- **Expect 1-2 rejected drafts per 10 and budget one repair round each.** In this pass the
  write path caught: a reference solution that disagreed with its own test, an expected
  frame count off by one, a float tolerance too tight for the `eps` in the formula
  underneath it, and a mel-filterbank claim that is false at a 400-point transform (the
  lowest filters collapse to zero width). None would have been caught by reading.
- **Two cheap authoring rules that avoid most rejections.** (1) Never assert an exact
  count you have not computed — run the reference solution first and paste the number.
  (2) `gateaudit` needs the test to fail an empty submission *and* the starter stub, so
  make the first assertion compare against a concrete value rather than a shape.
- **A test that fails because coverage rose is the tool working.** Four have now moved
  (`test_gateaudit`, `test_regate`, and two in `test_launcher_api`). The newest:
  "a module carrying no gate locks nothing" could no longer find such a module in the
  seed library, so it now asserts the rule against `progress.module_gates()` directly.
  When you hit one, move the claim to where the rule lives; do not freeze the corpus.
- **The `notebooks/ungated.json` register must be kept current by the next batch.** Gating
  a domain to 100% makes its entry stale, and `tests/test_ungated.py` will say so.

**Learnings for future iterations**
- **The floor is not coverage, and the code says so out loud.** `coverage.py`'s rule is
  "no number here is ever stored"; the ratchet keeps it by never *reading* the stored
  number as coverage — coverage is always measured, the floor is always loaded, and the
  only thing compared is the direction. Keep that split if you extend it.
- **`measure()` folds `backfill.coverage()`, not a new scan.** That is what keeps
  `is_gated()` the single definition of a gate *and* makes the check core-only (no
  fastapi, so it does not `importorskip` itself away in a bare environment).
  `tests/test_gatefloor.py` pins it against the view-model report as well, so the two
  altitudes still agree.
- **A doc claim that a test reads must be strict about its own shape.** `CLAIM` is a
  precise regex over one README sentence and `claim()` *raises* when it is gone — a loose
  pattern would keep matching after somebody rewrote the paragraph, which is the failure
  mode this whole story is about. `record()` rewrites the floor and the sentence together
  for the same reason; do not hand-edit one.
- **`write_claim()` substitutes a single line**, so keep the claim sentence on its own
  line in the README or a `--record` will unwrap the paragraph around it.
- **Raising coverage from here is two commands**, in this order: gate the notebooks, then
  `python3 -m praxis.gatefloor --record` (and update `notebooks/ungated.json`, which
  `tests/test_ungated.py` will otherwise report as stale).
